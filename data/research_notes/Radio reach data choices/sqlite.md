# SQLite spatial choices for the FCC FM reach pipeline

## 1. What do the current database and runtime actually support?

### Takeaway
The current stack already maps contours and has the machinery for a cheap bounding-box index. It does not currently compute exact contour–Census overlays or owner-level dissolved reach. The least disruptive architecture is to do the geometry work at build time and publish ordinary SQLite results plus display GeoJSON through the existing Datasette command.

### Cited findings
- The project asks for geographic reach by top-level owner and demographic joins. The FCC input covers FM services, not AM. Its modeled contours have service/class-dependent thresholds, not a single reception criterion; the FCC describes site coordinates as “NAD83/WGS84” and orders the 360 contour points clockwise from true north. The builder swaps `lat,lon` to `[lon,lat]`, closes the ring, retains raw text, drops duplicate rows, and indexes `(lms_application_id,dts_site_number)`. It does not test full geometric validity. [Project README](../../README.md) · [Builder, lines 43–119](../../scripts/create_db.py#L43-L119) · [FCC methodology/fields](https://www.fcc.gov/media/radio/fm-service-contour-data-points)
- **Local observations, 2026-11-21:** `data/.venv/bin/python`, macOS arm64: Python 3.15.2, linked SQLite 3.54.1, pandas 3.0.6, Datasette 0.65.5, datasette-geojson 0.4.0, datasette-geojson-map 0.5.0, datasette-leaflet 0.2.2, datasette-json-html 1.0.1. In-memory `pragma module_list` included `rtree`, `rtree_i32`, `geopoly`; `pragma compile_options` included `ENABLE_RTREE` and `ENABLE_GEOPOLY`; creating both virtual tables succeeded. The Python extension-loading switch could be enabled then disabled; `spatialite_version()` and `tg_version()` were unavailable on a fresh connection. No Shapely, pyproj, GeoPandas, Pyogrio, GDAL Python distribution, Fiona, DuckDB, sqlite-tg, sqlite-utils or APSW distribution found in that venv; no `ogrinfo`, `gdalinfo`, `spatialite` or `duckdb` on this process's PATH. This describes the probed interpreter, not every SQLite binary on the machine. [Dependency declaration](../../pyproject.toml) · [Lockfile](../../uv.lock) · [Python SQLite runtime API](https://docs.python.org/3/library/sqlite3.html)
- **Local read-only database probe:** `sqlite3.connect('file:data/public_radio_facility_data.sqlite?mode=ro', uri=True)` from repo root. `PRAGMA table_info(fm_service_contour)` showed seven TEXT columns including `contour` and `geometry`; `PRAGMA index_list` found only the unique application/site key. No virtual tables or `gpkg_contents`, `geometry_columns`, `spatial_ref_sys` in schema. One `LIMIT 1` sample had JSON type `Polygon`, 361 ring positions and first position `[-119.79961,39.63289]`, matching raw `39.63289 ,-119.79961`. This is a spot check, not a quality census. [Local DB](../../public_radio_facility_data.sqlite) · [Builder](../../scripts/create_db.py#L63-L119)
- `make launch-datasette` opens the database immutable (`-i`) and sets a 20 s SQL limit. The map plugin recognizes and renders geometry; the GeoJSON output plugin serializes results. Neither supplies a spatial SQL engine, projection, or exact overlay. [Launcher](../../Makefile#L27-L28) · [Map plugin](https://datasette.io/plugins/datasette-geojson-map) · [GeoJSON output](https://datasette.io/plugins/datasette-geojson)

### Inferences
- Keep site/application provenance through selection of in-scope facilities, active contour versions and owner mapping. Dissolve only after the editorial definition of reach is known. Keep modeled reach distinct from reception measurements or listener counts.

### Gaps
- No geometry library installation, deployment, full scan, download of geographic datasets, or runtime benchmark was performed. The sample and switches above do not establish topology, release-wheel compatibility, or throughput.

## 2. Which SQLite options meet which requirements?

### Takeaway
**SpatiaLite** is the full spatial SQL option here. **SQLite R\*Tree + offline Shapely/pyproj** is the practical alternative when maintaining ordinary SQLite/Datasette is more important than live overlay SQL. Geopoly and TG are useful for narrower questions. A file format, a map renderer, a spatial index and an overlay engine solve different problems.

### Cited findings

| Option | Geometry, index and useful operations | Limit for this application |
|---|---|---|
| **SQLite R\*Tree** | Virtual table `rtree(id,minx,maxx,miny,maxy)` indexes envelopes keyed by 64-bit integer; geometry can live in another ordinary table as full-precision WKB or GeoJSON. Ordinary float R\*Tree bounds are 32-bit, rounded outward: use inclusive overlap tests; containment-only searches need care near boundaries. [SQLite manual](https://sqlite.org/rtree.html) | No polygon topology, CRS, intersection geometry or union. Maintain index with rebuild/transactions or triggers; preserve stable integer feature key alongside external application/site or text GEOID. A local `:memory:` right triangle `(0,0),(2,0),(0,2)` returned one envelope hit for `(1.5,1.5)` but `geopoly_contains_point` returned **0**. |
| **Geopoly** | Optional SQLite amalgamation module. Stores one simple 2D polygon as a custom float32 BLOB; accepts a *single closed coordinate ring*, not a GeoJSON geometry object. `geopoly_ccw` fixes clockwise winding. Supports overlap, within, point membership (includes edge), planar area and affine transform. Bare `WHERE geopoly_overlap(_shape,:ring)` and `geopoly_within` can use its R\*Tree; local query plan reported `VIRTUAL TABLE INDEX 2:rtree`. [SQLite Geopoly](https://sqlite.org/geopoly.html) | No holes, multipolygons, constructive intersection, dissolve or CRS reprojection. Its affine transform is not a datum/projection engine. Taking only `$.coordinates[0]` from a Census polygon with holes changes the answer. A fit only for validated simple-ring lookups, not owner unions or area weights. |
| **SpatiaLite (`mod_spatialite`)** | Native SQLite extension: registered typed geometry/SRID columns, native SpatiaLite BLOBs, WKB/WKT/GeoJSON conversion, multipart/hole support, GEOS predicates and constructive operations (`ST_Intersects`, `ST_Intersection`, `ST_Union`), planar `ST_Area`, validity checks, PROJ-backed `ST_Transform`. `InitSpatialMetaData`, `AddGeometryColumn`, `CreateSpatialIndex` build metadata and a trigger-maintained R\*Tree. Use explicit `SpatialIndex` subquery with `search_frame` then exact predicate; the presence of an index alone doesn't prove it was used. [Function list and build dependencies per function](https://www.gaia-gis.it/gaia-sins/spatialite-sql-5.1.0.html) · [SpatialIndex guidance](https://www.gaia-gis.it/fossil/libspatialite/wiki?name=SpatialIndex) · [BLOB format](https://www.gaia-gis.it/gaia-sins/BLOB-Geometry.html) | A native installation per build/runtime that executes those functions; check version and optional capabilities (e.g. validity repair) rather than assuming every build is identical. Native BLOB ≠ plain WKB ≠ GeoPackage BLOB. Export via conversion functions or a driver. |
| **TG / sqlite-tg** | TG is a C library for geometry parsing and predicates with optional *within-geometry* acceleration; sqlite-tg wraps it for SQL, accepting GeoJSON/WKT/WKB, including multipart geometries. Tagged release documents `tg_intersects`, `tg_covers`, and experimental `tg0` virtual table with *between-feature* R\*Tree acceleration for `tg_intersects(_shape,...)`. These two index levels are distinct. [TG](https://github.com/tidwall/tg) · [Tagged SQLite API](https://github.com/asg017/sqlite-tg/blob/v0.0.1-alpha.21/docs.md) | Upstream calls it work-in-progress. Boolean intersection ≠ construction of an intersection: tagged API does not document area, constructive intersection, dissolved union or CRS transformation. Suitable for a pinned predicate-only pilot on existing GeoJSON; do not rely on unreleased `main` docs. PyPI returned **0.0.1a21** for both packages, with platform-specific sqlite-tg wheels for macOS arm64/x86_64, manylinux aarch64/x86_64 and Windows amd64, and a separate Datasette plugin. [Upstream installation/status](https://github.com/asg017/sqlite-tg) · [PyPI file list](https://pypi.org/project/sqlite-tg/0.0.1a21/#files) · [Plugin](https://pypi.org/project/datasette-sqlite-tg/) |
| **Offline GEOS/PROJ via Python** | Use Shapely to decode geometries, validate/repair under policy, build an in-memory STRtree, query candidates with an exact predicate, compute intersections, areas and `union_all`; use pyproj for CRS transformation with explicit XY order. Persist results in ordinary SQLite. WKB plus explicit layer CRS is convenient for offline interchange. [Shapely STRtree](https://shapely.readthedocs.io/en/stable/strtree.html) · [Shapely set operations](https://shapely.readthedocs.io/en/stable/set_operations.html) · [pyproj Transformer](https://pyproj4.github.io/pyproj/stable/api/transformer.html) | STRtree is query-only and rebuilt in memory. SQLite R\*Tree is useful if candidate filtering must persist between runs; both indexes are not mandatory. Python wheel/GEOS/PROJ support must be checked for the selected Python and CI platform. |
| **GeoPackage / GDAL** | GeoPackage is standardized SQLite storage: feature/CRS metadata, GeoPackageBinary header + WKB, and standardized optional RTree spatial-index extension. GDAL/OGR reads/writes it, Shapefile and GeoJSON; the SQLite driver can produce SpatiaLite with `-dsco SPATIALITE=YES` when supported. GDAL's SQLite dialect/VirtualOGR can expose other vector formats to SQL. [OGC standard](https://www.geopackage.org/spec/) · [GDAL GPKG driver](https://gdal.org/en/stable/drivers/vector/gpkg.html) · [GDAL SQLite driver](https://gdal.org/en/stable/drivers/vector/sqlite.html) | Excellent exchange artifact for QGIS or to ingest Census boundaries. Merely renaming `.sqlite` or opening a `.gpkg` in stock sqlite3 does not add `ST_Intersection` or make arbitrary BLOBs usable by TG/Shapely. Use format-aware adapters; check the actual GDAL build/drivers. |
| **DuckDB spatial (contrast)** | SQL engine with GDAL readers, geometry, indexes and constructive spatial functions. Can run a separate batch and export tables for SQLite/Datasette. [Extension](https://duckdb.org/docs/stable/core_extensions/spatial/overview) · [Functions](https://duckdb.org/docs/stable/core_extensions/spatial/functions) | A different engine and runtime; not a SQLite loadable module or a drop-in Datasette DB. Compare on actual joins/build sizes before choosing for speed. |

### Inferences
- Pick SpatiaLite if reproducible **SQL-native** exploratory clipping and dissolve are first-class needs. For a periodic static dashboard, isolate the geometry dependencies in the builder and publish precomputed owner/geography/method/version rows and WGS84 display polygons. Do not simplify the measurement geometry to speed map rendering; simplify a separate display derivative.

### Gaps
- No cross-engine performance ranking or promise of support for every optional function. Local TG/SpatiaLite/GEOS behavior was not executed.

## 3. How should filtering, measurement, packaging and validation work?

### Takeaway
First reduce candidate pairs by bounding box, then test the actual geometries, then measure positive-area intersections in an appropriate equal-area CRS. Do not sum station overlaps to get unique owner coverage or mistake covered land fraction for measured population reach.

### Cited findings
- **Projection policy:** RFC 7946 display coordinates are WGS84 longitude/latitude. Keep documented source datum, axis order, edition and transform separately for each layer. `SetSRID` labels coordinates; `ST_Transform` changes them. Planar area in degrees² or Web Mercator is unsuitable for physical-area weights. NAD83 / Conus Albers EPSG:5070 is a metre-based equal-area CRS for CONUS; Alaska Albers EPSG:3338 is an Alaska example. Select appropriate documented equal-area CRS for Hawaii/territories as needed; handle antimeridian-crossing geometries before constructing planar rings/envelopes. [RFC 7946 §§3.1.9, 4](https://www.rfc-editor.org/rfc/rfc7946) · [5070](https://spatialreference.org/ref/epsg/5070/) · [3338](https://spatialreference.org/ref/epsg/3338/) · [SpatiaLite functions](https://www.gaia-gis.it/gaia-sins/spatialite-sql-5.1.0.html)
- **Deployment:** On macOS Datasette documents `brew install spatialite-tools`; on Debian/Ubuntu `libsqlite3-mod-spatialite` (plus `spatialite-bin` for CLI). Load **mod_spatialite**, not generic `libspatialite`, using discovered native path, e.g. `datasette --load-extension=spatialite` or absolute dylib/so. Match process architecture; don't hard-code an Intel or Linux path. Native dependency versions are not governed by this project's uv lock. SQLite extensions load on each connection; for a controlled builder enable loading, load a trusted fixed path, disable loading immediately. Some macOS Python builds omit this API. For public live spatial SQL use vetted canned queries and restrict arbitrary SQL (`--setting default_allow_sql off`); immutable mode is not a substitute. No runtime extension needed to serve materialized plain data. [Datasette install/security guidance](https://docs.datasette.io/en/stable/spatialite.html) · [SQLite extension loading](https://sqlite.org/loadext.html) · [Python sqlite3](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.enable_load_extension)

### Inferences
1. Preserve original geometry, check counts, finite/range-valid XY, closure, polygonal type, self-intersections, missing inputs, holes, duplicate application/sites, dateline and active-status decisions. Quarantine or log every repair including change in area; repair can yield mixed dimensions. Transform both layers to the same analysis CRS before building the analysis index.
2. Dissolve selected FM contours by top-level owner, vintage and region (`ST_Union` aggregate or `union_all`), or union clipped pieces per owner/geography where nationwide owner envelopes give poor selectivity. Retain membership for audit. For all-owner unique reach dissolve across owners separately. Different owners can legitimately cover the same person.
3. Given projected polygonal `owner_region.geom` and an indexed same-CRS `census.geom`, the following illustrates the **SpatiaLite candidate + recheck** (proposed SQL, not run locally; [upstream pattern](https://www.gaia-gis.it/fossil/libspatialite/wiki?name=SpatialIndex)):

   ```sql
   SELECT o.owner_id, c.geoid, ST_Area(ST_Intersection(o.geom,c.geom)) AS covered_m2
   FROM owner_region AS o JOIN census AS c
     ON c.rowid IN (SELECT rowid FROM SpatialIndex
                    WHERE f_table_name='census' AND f_geometry_column='geom'
                      AND search_frame=o.geom)
    AND ST_Intersects(o.geom,c.geom)=1;
   ```

   With plain `rtree`, candidate predicate for envelope `q` is `xmin <= q.xmax AND xmax >= q.xmin AND ymin <= q.ymax AND ymax >= q.ymin`; fetch original full shapes by ID for the recheck. `ST_Intersects` includes boundary-only touches; retain only positive polygonal area for weights. Choose `Covers` vs `Contains` deliberately for point proxies on boundaries. Check query plan and measure candidate pairs, exact hits, positive-area hits, timings and peak memory on representative rural, urban, coastal and multipart cases. Compare a small brute-force geometry baseline; indexes should change cost, not answers.
4. Divide intersection area by the geography's area on the **same support** (full polygon vs explicitly land-masked shape); don't divide a water-inclusive numerator by published land-only area. Guard null/zero denominators, inspect slivers and weights outside `[0,1]`; sum weighted *counts*, not percentages. Area-weighted population assumes uniform distribution within that geography. Label assumption and vintage; compare block representative-point counts or finer population allocation before claiming demographic precision.
5. CI smoke test in the actual interpreter/container: report SQLite version and module list, exercise a triangle bbox false positive, a hole, multipart islands, touching-only edges, duplicate owner contours and a known projected-square area. For SpatiaLite record `spatialite_version()`, `geos_version()`, `proj4_version()` and perform a known transform/overlay; verify PROJ resources and module availability on CI and serving hosts if used there. Check publishing works with the present immutable launcher and ordinary materialized GeoJSON/scalars. Benchmark build cost separately from Datasette request latency.

### Gaps
- Appropriate Census vintage/geography, land support, owner selection, definition of population allocation and deployment target are study decisions. No national benchmark, verified regional grid installation or representative coverage estimate follows from the toy probes.
